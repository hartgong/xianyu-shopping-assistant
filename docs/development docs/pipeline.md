# 现有流程：采集 → 粗筛 → 细筛 → 询价

## 总览

任务只执行“本次执行阶段”中勾选的步骤。未勾选细筛时，粗筛完成后立即停止，绝不打开任何商品详情页。

```text
登录验证
  ↓
按多个关键词的 AND 关系搜索并采集商品
  ↓
按商品 ID 去重、保存价格快照
  ↓
粗筛：列表页硬性规则
  ↓
细筛：逐商品打开详情页 → 提取详情与卖家信息 → 详情页硬性规则
  ↓
待人工确认
  ↓
人工勾选商品后，进入询价
```

任务的常规启动入口在 `lib/task.mjs`。默认在细筛结束后进入 `review` 状态，并停止流程。

## 1. 采集

### 输入参数

任务可配置：

- 最多四组搜索关键词；每组内部为 AND 关系，填写的每组分别执行一次闲鱼搜索。
- 最低价、最高价
- 地区
- 是否仅“个人闲置”
- 最大搜索页数，默认 3 页

配置定义在 `lib/task.mjs` 的 `_buildTaskConfig`。

### 执行方式

将逗号分隔的全部关键词组合为一条闲鱼搜索请求，并仅保留标题同时命中全部关键词的商品：

1. 将全部关键词以空格组合，打开 `https://www.goofish.com/search?q=<组合关键词>`。
2. 等待页面加载及人工验证状态。
3. 根据任务配置尝试应用“个人闲置”勾选、价格区间及省/市地区。
4. 逐页采集，直到达到最大页数、没有下一页，或任务被停止。
5. 每页会先自动滚动以加载更多卡片，并在本地仅保留标题包含全部关键词的商品；不为关键词验证打开详情页。

“最大页数”是本次组合关键词搜索可翻阅的闲鱼搜索结果页数，不会按关键词倍增。

核心逻辑位于 `lib/search.mjs` 的 `searchProducts`。

### 采集字段

列表页当前采集：

- 商品 ID、链接、标题、价格、价格描述
- 包邮状态
- 想要人数及文本
- 卖家地区
- 商品主图

### 去重与价格记录

同一任务中以商品 ID 去重；重复采集时更新商品快照，并记录：

- 首次发现、最近发现时间
- 当前价、上次价格、价格涨跌
- 最近 20 条价格历史

## 2. 粗筛

粗筛输入是所有去重后的采集商品，逻辑位于 `lib/filter.mjs` 的 `coarseFilter`。

### 第一层：硬性规则

无需调用 AI，逐件排除：

- 价格低于最低价或高于最高价；
- 标题命中排除词；
- 要求包邮但商品不是包邮，或未标明包邮；
- 想要人数低于设定阈值。

粗筛不调用 AI。所有条件均来自列表页，并由价格、标题排除词、包邮和想要人数等可配置硬规则决定。

## 3. 细筛

细筛只处理粗筛通过的商品，逻辑位于 `lib/filter.mjs` 的 `fineFilter`。

### 单件详情采集

每件商品会单独打开详情页并提取：

- 描述、详情页价格、图片；
- 卖家昵称、地区、好评率、最近活跃状态；
- 卖家头像 URL 及其规范化头像指纹（以详情页的最新头像为准）；
- 卖出/成交量、在售/发布量；
- 想要人数、浏览量、发布时间或更新时间；
- 包邮状态；
- 商品聊天链接、卖家 ID；
- 卖家主页/相关商品区域中可见的文本。

每处理一件商品后，会随机等待 5–12 秒。

### 小B 排除逻辑

细筛的唯一自动目标是识别二奢小B；它不会自动把任何卖家判为个人卖家。自动结果可为 `小B`、`疑似小B` 或 `不明确`。五档等级 `小B`、`个人卖家`、`疑似小B`、`疑似个人卖家`、`不明确` 仍可由人工标注。

自动小B判断只使用两类证据：

1. **二奢经营词**：命中卖家昵称或卖家店铺简介，例如实体店、批发、寄售、回收等。
2. **真实在售结构**：卖家主页中、且卡片文字包含该卖家昵称的在售商品标题，命中二奢商品词库后的数量或占比达到本任务阈值。

第一类为强证据，直接自动标为 `小B`，并在细筛表以“⚠ 小B（经营词）”保留显示；第二类仅标为 `疑似小B`，等待人工确认。

当前商品标题与描述、卖家交易/卖出量、卖家在售总量、个人卖家词、日常闲置品词均不参与等级判断。这样避免小B伪装个人文案或其他品类商家偶尔出售一件奢侈品时被错误排除。

输出包括 `sellerType`、`sellerProfileReason`、经营词命中项、二奢样本数量和占比。`sellerPersonalScore` 保留为兼容历史数据，不再作为判断依据。

### 人工标注与黑名单

当前已具备两项基础能力：

- 配置中的卖家黑名单会在细筛时直接跳过；
- 卖家人工标签会覆盖自动画像的展示结果。

卖家头像指纹是去除图片尺寸后缀的头像 URL，不是平台唯一 ID。列表页先以它作为弱关联依据；细筛打开详情页后会以最新头像覆盖。人工标为小B时，系统同时保存可用的 `sellerId`、头像指纹和昵称键；后续粗筛可凭头像指纹直接排除，详情页有 `sellerId` 时优先使用它。

### 细筛访问与可配置参数

细筛不调用 AI。它先打开商品详情页取得卖家主页 URL、卖家 ID 与最新头像；同一卖家最多额外访问一次 `personal?userId=…` 主页，读取店铺简介和在售卡片。只有卡片文字包含当前卖家昵称才计入样本，避免详情页“为你推荐”混入其他卖家。已读取成功的卖家主页快照会复用，避免重复访问。

新建任务可设定：在售采样数（默认 20）、二奢数量阈值（默认 5 件）、二奢占比阈值（默认 40%）和高风险占比提示（默认 60%）。数量或占比达到阈值即自动标为 `疑似小B`。高风险提示仅增强展示，不新增判定规则。

词库仅维护两类：二奢经营词（只检查卖家昵称、店铺简介）与二奢商品词（只检查真实在售列表标题）。二者不可混用。

卖家池提供“店铺”快捷入口，可直接人工核对店铺介绍、在售／已售数和在售卡片；随后点击等级标签记录五级人工结论。核验后的卖家档案会复用主页快照，调整阈值后可用“重新细筛”验证规则，而不必重复打开同一卖家主页。

商品标题本身不属于经营词判定对象；它只会作为卖家真实在售列表中的一条样本，参与二奢数量／占比计算。经营词自动确认的 `小B` 与人工确认的 `小B` 都会在后续粗筛排除。

页面会同时保留两种计数：**已核验**表示实际打开并完成细筛判断的商品数；**细筛可跟进**会排除小B与疑似小B，表示可以进入后续人工确认／询价的商品数。自动确认小B与`疑似小B`都完整显示在细筛表中，并以醒目红色提醒优先核查。细筛操作栏提供就地下拉标记，无需打开弹窗；只有 `sellerManualLabel` 代表人工确认等级。

细筛列表默认按卖家等级排序：`小B`、`疑似小B`、`不明确`、`疑似个人卖家`、`个人卖家`。`小B（经营词）`中的括号是自动判断来源，不是新等级；它由 `sellerAutoConfirmed` 记录。人工标为小B后页面仅显示“小B”，不再显示该来源后缀。

二奢词库可从“设置 → 二奢卖家词库”编辑，仅含二奢经营词和二奢商品词。采集时会先建立列表页“待核验”卖家档案，以便每个已识别卖家进入卖家池；该档案绝不会让首次细筛跳过详情页。只有详情页细筛或卖家池“核验”成功更新过的档案，才可按卖家 ID、头像指纹或完整昵称复用并避免再次打开详情页。详情页获取到新头像时会写入最新指纹。

卖家池的“核验”按钮是唯一的手动强制复核入口：它打开卖家的最近商品详情页，更新卖家 ID、最新头像、卖家主页快照和小B证据。该操作仅在用户点击时发生。

“卖家池”是右上角独立的跨任务闲鱼卖家档案库，不属于采集、粗筛、细筛、询价流程。只有取得可靠卖家昵称或卖家 ID 的商品才会同步档案；头像 URL 仅用于已确认身份后的合并，不能单独建档。搜索列表页显示的地区不会再被当作卖家昵称。同一卖家优先按卖家 ID、其次头像指纹、最后昵称合并。它支持按昵称、卖家 ID、头像指纹、最近商品和判断证据搜索，并可按全部五级卖家等级筛选。人工标记或经营词自动确认小B后会同步更新卖家池，并在之后的粗筛阶段直接排除。细筛写入后会主动推送卖家池更新；打开卖家池时还会重新读取服务端数据，避免页面缓存显示为空。

卖家标记只接受卖家昵称、卖家 ID 或头像指纹；地区字段不能作为卖家身份，历史上缺少卖家身份的数据不能安全回填到商家池。

卖家池不再从本地历史任务迁移档案；卖家档案只由 Turso 云端提供。历史列表页只有地区、没有卖家身份的信息不可直接人工标记。

粗筛仅展示已有卖家档案的等级，不提供人工标记；五级人工卖家标记只在细筛结果中开放。

细筛商品的“操作”栏提供“标记卖家”按钮，点击后可选择五级卖家等级。

卖家池中的等级标签可直接点击修改；修改后仍保留在卖家池中，并更新所属等级。

## 4. 询价

细筛结束后默认进入“待确认”状态：

```text
细筛完成 → 用户勾选商品 → 点击“开始询价” → 才进入询价阶段
```

AI 仅用于询价。新建任务时可以勾选是否执行 AI 询价；未勾选时，任务在细筛后进入待确认状态。

## 维护约定

任何修改采集、粗筛、细筛或询价流程的开发工作，都必须在同一变更中同步更新本文档。

## 测试数据重置

测试新逻辑前，可在**停止服务后**执行 `npm run reset:test-data -- --yes`。该命令会清空本机任务和测试结果，但保留 API 设置、模型、二奢词库、黑名单和跟踪商品。执行后重新启动服务。

已启用 Turso 共享卖家池时，该命令不会删除云端卖家档案或人工标记。云端卖家档案请通过 Turso 管理界面维护。

新建任务默认值：任务名提示为 `LV`、最大页数为可手动输入的 `1`、列表排序为“新发布”、最低价为 `500`、标题排除词为“求购、维修、养护、配件”。

新建任务中的“聊天”和“AI 询价设置”均默认折叠。首页刷新后，默认选中任务列表的第一项；WebSocket 重连不会改变用户已选择的任务。

新建任务默认主按钮为“创建并启动”；其左侧提供灰色“仅创建”按钮。仅创建会保存任务配置但不启动采集，后续可从任务详情启动。

新建任务的分组为下拉列表，自动汇集现有任务分组，并提供“未分组”与“＋ 新建分组…”选项；选择后者可直接输入新分组名称。

## Chromium 正常退出

Chromium 使用持久用户目录保存登录状态。服务收到 `Ctrl+C` 或系统终止信号时会先关闭 Chromium 上下文，再退出，避免下次启动出现“未正确关闭”提示。请通过 `Ctrl+C` 停止服务，不要直接强制结束 Node/Chromium 进程。

异常退出后，如果 Chromium 的资料目录留下 `SingletonLock`，程序会仅在确认其记录的**本机 Chromium 进程已不存在**时，清理该锁并重新启动浏览器；登录资料不会被删除。若任务仍失败，完整的 Playwright 启动错误会同时写入任务日志和 `.runtime/server.log`。

## 共享卖家池（Turso）

任务、商品结果和浏览器登录态仍保存在各电脑本地；只有卖家档案与人工卖家等级可以同步到 Turso 云端 SQLite。未配置 Turso 时，程序完全沿用本地 JSON 卖家池。云端以 `sellers` 保存“一卖家一主档案”，以 `seller_fingerprints` 保存头像 URL 指纹及其归属和发现时间；昵称仅是主档案的可变资料，不是云端卖家主键。

在每台电脑的项目根目录创建 `.env`（可从 `.env.example` 复制），填写同一个数据库的：

```text
TURSO_DATABASE_URL=libsql://...
TURSO_AUTH_TOKEN=...
```

密钥不得提交到 Git。Turso 是卖家池与头像指纹的唯一真实来源：服务启动、每次任务启动和每次打开卖家池都会直接读取云端；列表页或细筛写入卖家档案、人工标记卖家等级后，会直接回写云端。本地 JSON 不再保存或参与卖家池合并。共享连接状态可通过 `GET /api/seller-pool/status` 查看。
